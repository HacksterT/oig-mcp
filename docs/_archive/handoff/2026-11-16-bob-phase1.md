## Findings and recommendations

**Root cause of first-run failures:** The VM's `umask` defaults files to owner+group only (mode 640/750). Docker's `COPY` preserves those modes. The non-root uid 10001 is not in root's group, so it could not enter `/app/src/oig_mcp`. The fix (`chmod -R a+rX` before `uv sync`) is now in `main`. This did not appear on the Mac because macOS file permissions default to world-readable.

**Process note:** Per note2, fixes to repository files go through Troy's Mac to `main`. Bob reports the problem with exact error and proposed fix, then stops. This was followed correctly.

**Assumptions confirmed:**
- A2: Podman 5.4.0 works correctly as the container engine. `--platform` was not needed.
- A3: `docker.io/library/python:3.11-slim` pulled cleanly from the VM. PyPI is reachable during build.
- A4: VM is `x86_64`; base image matches natively.
- C2: The VM reaches Cloudflare with no proxy or allowlist needed. The status tool returned live data.
- C3 (partial): Cloudflare admitted the VM's IP. Still to be confirmed from Code Engine in Phase 2.

**`useradd` warning** (`oig's uid 10001 is greater than SYS_UID_MAX 999`) is cosmetic — the user is created and the app runs correctly as uid 10001.
